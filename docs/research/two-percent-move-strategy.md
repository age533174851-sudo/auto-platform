# 2% 양방향 움직임 포착 전략 — 검증 설계 (연구 전용)

상태: **연구 계획, 미검증**. 매매 로직/주문/DB/설정 변경 없음.

## 목표와 용어
- 대상은 **기초자산 가격 자체의 2% 이상 이동**이다. 레버리지 수익률 2%가 아니다.
- LONG/SHORT를 대칭적으로 평가한다. 사후에 2% 이동을 알았다는 사실과 사전 포착은 다르다.
- 2% 움직임 **전부 포착을 보장하지 않는다**. 진입 이후 실제 순포착률과 손실을 함께 평가한다.
- 고정 익절을 강제하지 않고 매일 한국시간 오전 9시를 진입 판단 기준으로 삼고, 진입 후 다음 판단 창까지 지속적으로 청산 신호를 평가하는 후보를 비교한다. 4시간 또는 24시간 보유를 목표로 하지 않는다. 기존 Exact100X `NO_FIXED_SL`/`NO_FIXED_TP` 계약을 변경하지 않는다.

## 현행 코드 감사 기준 (main f902be8)
- `src/lib/strategies/scalpSignal.ts`: 최근 20봉 고/저점 돌파, 거래량 평균 1.3배, ATR(14), RR 2, 왕복비용 0.15% 가정.
- `src/lib/strategies/scalpRun.ts`: `toStandardSignal`의 confidence는 상수 0.5. 신호 품질에 따른 동적 포지션 조절의 근거가 아니다.
- `src/lib/strategies/exitPolicy.ts`: `testnet-exit-v1`은 별도 검증용 0.4% stop / 0.8% TP; Exact100X 계약과 혼동 금지.
- 현재의 `scalpSignal`은 **2% 이상 미래 움직임의 예측확률/기대값을 계산하지 않는다**. 이를 구현했다고 주장하지 않는다.

## 연구 실험 설계 (실행 로직 미연결)
1. 데이터: 거래소별 심볼, UTC 시간, 봉 주기, OHLCV, 수수료/슬리피지/펀딩, 상장폐지·결측 여부 기록. 진행 중인 봉의 미래 고저가를 사용하지 않는다.
2. 레이블: 신호 시점 t 이후 **사전에 정한** 1h/4h/6h/12h/24h 내 롱 +2% 또는 숏 -2% 도달 여부를 각각 산출한다. 같은 구간에 양쪽이 모두 닿으면 순서 불명인 봉은 `AMBIGUOUS`로 분리한다.
3. 비교군: 기존 돌파+거래량 전략 vs 추세/변동성/거래량 레짐 필터 추가 후보 vs 후보 + 09:00 진입 판단·상시 청산 감시. 거래 빈도를 억지로 늘리지 않는다.
4. 검증: 시간 순서 train/validation/test 분리, walk-forward, 심볼·레짐별 분리, 겹치는 보유구간 누수 방지, 수수료·슬리피지·펀딩 민감도 분석.
5. 지표: 2% 이동 발생 빈도, 사전 탐지 precision/recall, 실제 가격 움직임 포착 비율, 거래당 순기대값, 최대 낙폭, 청산/강제종료 빈도, 롱·숏 성적 별도, 평균 보유시간, 09:00 진입 판단 이행률, 청산 신호 발생부터 주문까지 지연, 감시 누락 시간, 재시작 후 청산 감시 복구율.
6. 탈락 기준: out-of-sample 기대값 ≤0, 거래비용 반영 후 성적 역전, 청산거리/가격 신선도 검증 실패, 결측/모호한 데이터에 낙관적 체결 가정이 필요한 후보.

## 사용자 요구: 09:00 진입 기준 + 지속 감시 + 신호 기반 청산
- **매일 09:00 Asia/Seoul**을 진입 판단 기준으로 삼는다. 시장 상황에 따라 LONG/SHORT를 선택한다. 신호나 안전조건이 충족되지 않을 때의 주문 여부는 별도 정책으로 명시해야 하며 무조건 매수로 해석하지 않는다.
- 진입 후에는 포지션을 **지속 감시**하고 청산 신호가 발생하면 그때 청산한다. **4시간마다 청산/재매수하거나 24시간을 채워 보유하는 전략이 아니다.**
- 24시간은 매일 09:00~다음날 09:00의 관측/운영 창이다. 실시간 감시 주기, 청산 권한, 감시 중단 시 보호 동작은 코드 감사와 테스트로 확인해야 한다. 24시간 내 무조건 청산하라는 새 규칙을 임의로 추가하지 않는다.
- 현행 `MAX_LEV_100X.maxHoldSec=14400`은 **4시간 제한**으로 요구와 충돌한다. `lifecyclePolicy.ts`의 `scalp.maxHoldMs=6h`, `my-original-v1.maxHoldMs=24h`는 별도의 검증 정책이므로 Exact100X에 적용되는지 호출 경로 확인 전까지 단정하지 않는다.
- 시간 제한을 단순 제거하면 감시 장애 시 무제한 방치 위험이 있으므로, 청산 신호·재시작 복구·감시 실패 안전동작을 먼저 검증한 뒤 기존 계약을 별도 PR로 변경한다.
- 하루 수익 보장이나 모든 2% 변동 포착을 주장하지 않는다.

## 100배 제약
- 100배 격리 포지션은 가격 2% 움직임을 기다리기 전에 반대 방향의 작은 변동으로 강제청산될 수 있다. **2% 목표와 100배 유지 가능성은 별개**다.
- 청산 거리·유지증거금·펀딩·실제 거래소 포지션 모드 확인 전에는 안전성을 주장하지 않는다.
- 전략 연구 결과가 나와도 LIVE 배포·TESTNET 주문·기존 자동매매 설정 변경은 별도 승인 전까지 금지.

## 구현 전 필수 감사
- A0: 09:00 KST 스케줄 트리거, 실행 중복 방지, 감시 워커의 호출 주기, 4시간 강제청산을 일으키는 실제 코드 경로, 신호 기반 청산의 권한/주문 배선을 각각 확인한다. 이 문서만으로 구현 완료라고 주장하지 않는다.
- A: 주문과 무관한 순수 `twoPercentMoveLabel` 계산기 + 경계/동시도달/누수 테스트.
- B: 기존 신호에 대한 과거 데이터 평가기와 비용 반영 지표.
- C: 필터/종료 후보 A/B 비교, out-of-sample 통과 시에만 별도 제안.
