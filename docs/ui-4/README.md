# UI-4 자동매매 화면 실측 결과

`scripts/probe/auto-targets.mjs`와 `scripts/probe/auto-header-overlap.mjs`가
실제 렌더에서 잰 값이다. base와 head를 각각 빌드해 **같은 검사기로**
측정했다.

| | |
|---|---|
| base | `454892ae349a25c29910ee1fe86ca1c171966a14` (UI-3C 종료 main) |
| head | 이 PR |

재현:

```bash
npm run build && npx next start -p 3900 &
node scripts/probe/auto-header-overlap.mjs 3900          # 상단 겹침
node scripts/probe/auto-targets.mjs 3900 /tmp/out 390x844 # 조작 대상 크기
node scripts/check-tap-targets.mjs                        # 소스 계약
```

## 떠 있는 알림 벨이 헤더를 덮었다

`NotifyHost`의 벨은 38×38로 `top:10 right:10`에 그냥 떠 있었다.
오른쪽 레일이 사라지는 1024px 미만에서 헤더의 마지막 버튼과 겹쳤다.

| 뷰포트 | base 겹침 | head 겹침 |
|---|---|---|
| 430×932 | 로그인(339–414) ↔ 벨(382–420) · **1376px²** | 0 |
| 390×844 | 로그인(299–374) ↔ 벨(342–380) · **1376px²** | 0 |
| 360×800 | 로그인(276–344) ↔ 벨(312–350) · **1376px²** | 0 |
| 834×1194 | 로그인(743–818) ↔ 벨(786–824) · **1376px²** | 0 |
| 1024×768 | 0 | 0 |
| 1366×768 | 0 | 0 |
| 1664×936 | 0 | 0 |

데스크톱에서 안 겹친 것은 접힌 오른쪽 레일(`RAIL_COLLAPSED` = 48)이
**우연히** 같은 폭의 띠를 비워 뒀기 때문이지, 누가 그렇게 정해서가 아니다.
그래서 그 띠를 계약으로 만들었다:

```
--tap: 40px          = panelPrefs.MIN_CONTROL_TARGET
--notify-band: 48px  = panelPrefs.RAIL_COLLAPSED (MIN_CONTROL_TARGET + 8)
```

벨은 그 띠 안에 들어가고, 레일이 없는 폭(<1024)에서는 헤더가 같은 띠를
비운다. 음수 마진이나 z-index로 밀어 넣지 않는다.

## 조작 대상이 손가락보다 좁았다

UI-1이 `MIN_CONTROL_TARGET`을 정본으로 정하면서 적어 둔 이유가 그대로
다시 났다 — "PC에서만 보인다"는 주석과 달리 CSS 계약은 768/1024px부터
보이는 것이고, 834×1194와 1024×768 태블릿은 손으로 누른다.

| 뷰포트 | base 40px 미만 | head |
|---|---|---|
| 390×844 | 11건 | **0** |
| 1664×936 | 11건 | **0** |

23곳의 숫자를 `MIN_CONTROL_TARGET`으로 바꾸고, 값을 안 적은 버튼은
`data-region="autoPage"` 한 줄로 바닥을 깐다. 글자 크기는 줄이지 않았다 —
누르는 자리를 넓힌 것이다.

base·head 모두 body 가로 넘침 0, 잘림 0, 세로로 쌓인 글자 0이다.

## 철회한 것

처음에 시세 띠(`.ticker`)를 "칸 밖으로 3,600px 넘침"으로 잡았다.
실제로는 마퀴 트랙이고 부모가 `overflow:hidden`으로 정확히 잘라 준다
(부모 폭 390, 트랙 4051). **그것을 "고쳤다면" 멀쩡한 시세 띠를
망가뜨렸을 것이다.** 검사기 쪽을 고쳤다 — 스스로 움직이는 칸과 조상이
스크롤 되는 칸은 세지 않는다.

폭 조절 손잡이(7px)도 뺐다. 손가락으로 누르는 대상이 아니고 터치
기기에서는 CSS가 숨기며, UI-1에서 키보드 경로를 따로 붙여 뒀다.
